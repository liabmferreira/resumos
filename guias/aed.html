1 · C para quem vem de Javaestudado ✓

Igual (quase)

  • tipos, literais, expressões, variáveis
  • if, switch, while, for, do-while (sem for-each)
  • funções em vez de métodos
  • bool existe (<stdbool.h>; antes usava-se int)

Diferente

  • Não há classes nem objetos: há struct, union, typedef
  • Arrays não sabem o tamanho e os índices não são verificados
  • Strings são arrays de char terminados em '\0'
  • Sem coleções, exceções nem genéricos
  • Memória gerida à mão: malloc/free
  • Ponteiros e aritmética de ponteiros

Compilar

cc -Wall -Wextra prog.c -o prog        # Linux (gcc no Windows)
./prog
cc -Wall -Wextra prog.c -o prog -lm    # se usar <math.h> (sqrt, floor, ceil)

Erro de compilação: viola a sintaxe ou os tipos, não gera executável. Aviso (warning): é C válido mas parece um bug; gera executável. Usa sempre -Wall -Wextra e corrige os avisos. -Wall apanha falhas comuns (variável não usada); -Wextra apanha mais (comparar inteiros com e sem sinal).

2 · Ponteiros, memória e funçõesestudado ✓

PonteiroVariável que guarda um endereço (índice do 1.º byte da variável apontada). &x dá o endereço de x; *p acede à variável apontada. NULL é o ponteiro que não aponta para nada válido: inicializa sempre com NULL e testa antes de usar.
int i = 10;
int* p = &i;        // p aponta para i
int* q = p;         // q também
*p = 5; *q = 20;    // i passa a 20
int a[3] = {1, 2, 3};
int* r = a;         // nome do array = endereço do 1.º elemento
*(a + 1) = 200;     // o mesmo que a[1] = 200
for (int k = 0; k < 3; k++) { printf("%d\n", *r); r++; }   // aritmética de ponteiros

Onde vive a memória

TipoQuando é criadaQuando é libertada

Local (stack)Na chamada da funçãoAutomaticamente no fim da função. Nunca devolver o endereço de uma local!
Dinâmica (heap)malloc(bytes) / calloc(n, bytes) (calloc põe a zero)Só com free(p). Sem garbage collector
double* v = malloc(N * sizeof(double));   // array dinâmico de N doubles
if (v == NULL) { exit(1); }                // a alocação pode falhar
v[0] = 3.5;
free(v);
v = NULL;      // free NÃO põe v a NULL: fazê-lo evita "dangling pointers"
Erros clássicosMemory leak: perder o último ponteiro para um bloco sem o libertar. Dangling pointer: usar um ponteiro depois de free ou para uma local que já acabou. Buffer overflow: escrever fora do array (strcpy não verifica tamanhos).

Passagem de argumentos

Em C tudo é passado por valor (cópia). Para uma função alterar uma variável do chamador, passa-se o seu endereço (call-by-pointer).

void swap(int* a, int* b) { int t = *a; *a = *b; *b = t; }   // troca de facto
swap(&x, &y);

struct Point { int x; int y; };
void ResetPoint(struct Point p)   { p.x = 0; p.y = 0; }        // altera a CÓPIA
void ModifyPoint(struct Point* p) { p->x += 10; p->y += 20; }  // altera o original
// p = {5,10} -> ModifyPoint(&p) -> {15,30} -> ResetPoint(p) -> continua {15,30}

struct, enum, typedef, assert, argc/argv

enum months { JANUARY = 1, FEBRUARY, MARCH };   // 1, 2, 3 (por omissão começa em 0)

Birthday b = {"joao", 2000, JANUARY};

int main(int argc, char* argv[]) { ... }   // argv[0] = nome do programa, argv[1] = 1.º argumento
Respostas aos exercícios da 2.ª parte de C
  • *ptr_i = 5; *another_ptr = 20; imprime 20.
  • sum = *p_a + *p_b vale 109 e não muda depois; a + b passa a 10999.
  • Array: *p_my_array = 30 imprime 30; *(my_array+1) = 200 imprime 200; o ciclo com ponteiro imprime 1 2 3.
  • Struct Point: 5 10, depois 15 30, depois continua 15 30.
  • V/F: (1) F, free não altera o ponteiro; (2) F, assert atua em execução; (3) V.

3 · Análise de complexidadeestudado ✓

AlgoritmoSequência de instruções não ambíguas que atinge um objetivo num tempo finito. Determinista: mesmos dados ⇒ mesmo resultado e mesma sequência de instruções. Não determinista: pode comportar-se de forma diferente com os mesmos dados (usado para soluções aproximadas).

Complexidade temporal

Nº de operações significativas (comparações, trocas, multiplicações…) em função do tamanho n.

Complexidade espacial

Memória extra necessária em função de n.

Análise experimentalAnálise formal
Correr com várias instâncias, contar operações ou medir tempo, deduzir a ordem a partir da tabela. Limitação: o tempo depende do hardware, compilador e carga do sistema."Papel e lápis": escolher a operação básica, escrever o nº de vezes que é executada como somatório, ver se a organização dos dados influencia, classificar.

Σ_{i=1}^{n} i²     = n(n+1)(2n+1)/6
Σ_{i=0}^{k−1} 2^i  = 2^k − 1
Σ_{i=0}^{k−1} i·2^i = 2^k (k − 2) + 2

Melhor, pior e caso médio

Para instâncias de tamanho n: B(n) = mínimo, W(n) = máximo e A(n) = Σ p(I)·t(I), a média pesada pela probabilidade de cada instância.

Receita do caso médio (abordagem estruturada)
  1. Definir o cenário (o valor existe? com que probabilidade?).
  2. Escolher a operação a contar.
  3. Listar os casos possíveis e quantos são.
  4. Contar as operações em cada caso.
  5. Atribuir uma probabilidade a cada caso (normalmente equiprováveis).
  6. Fazer a tabela e calcular A(n) = Σ prob × operações.
Exemplo: posição do máximo (searchMax) 
int searchMax(int a[], int n) {
    int indexMax = 0;
    for (int i = 1; i < n; i++)
        if (a[i] > a[indexMax]) indexMax = i;
    return indexMax;
}

Comparações: sempre n − 1 (não depende dos dados). Atribuições a indexMax (contando a inicial): melhor caso 1 (máximo em a[0]), pior caso n (array estritamente crescente).

A notação esquece constantes e termos de ordem inferior: 2n² + 3000n + 5 e 10n² + 100n − 23 são ambos Θ(n²). Para n grande o termo de maior grau domina (com n = 1000 já é 99,7 % do total).

Método: descobrir a ordem a partir de uma tabela de valores
  • n duplica e T(n) soma uma constante → logarítmica (ex.: 3, 4, 5, …, 13 para n = 1…1024).
  • n duplica e T(n) duplica → linear (ex.: 0, 1, 3, 7, …, 1023 = n − 1).
  • n duplica e T(n) quadruplica → quadrática (ex.: 1, 3, 10, 36, 136 = n(n+1)/2; ou 4, 12, 40, 144 = 2n² + 2n).
  • n aumenta 1 e T(n) duplica → exponencial (ex.: 1, 3, 7, 15, … = 2ⁿ − 1).
  • Cada valor é a soma dos dois anteriores (1, 2, 3, 5, 8…) → Fibonacci, exponencial (≈ 1,618ⁿ).

5 · Procura sequencial e procura bináriaestudado ✓

Sequencial em array não ordenado

int search(int a[], int n, int x) {
    for (int i = 0; i < n; i++)
        if (a[i] == x) return i;
    return -1;
}
CenárioB(n)W(n)A(n)
x existe (equiprovável)1n(n + 1)/2 ≈ n/2
x existe com probabilidade p1np(n+1)/2 + (1 − p)n ≈ n(1 − p/2)

p = 50 % ⇒ ≈ 3n/4; p = 25 % ⇒ ≈ 7n/8; p = 75 % ⇒ ≈ 5n/8.

Sequencial em array ordenado

int search(int a[], int n, int x) {
    int stop = 0; int i;
    for (i = 0; i < n; i++)
        if (x <= a[i]) { stop = 1; break; }   // pára assim que passa x
    if (stop && x == a[i]) return i;          // a ORDEM do && evita ler a[n]
    return -1;
}

B(n) = 2 (x ≤ a[0]); W(n) = n + 1 (x é o último ou está entre o penúltimo e o último). Com probabilidade de sucesso p: A(n) ≈ n/2 + 2 − p/2 (p = 20 % ⇒ n/2 + 1,9). Continua linear, mas é melhor que o caso não ordenado quando é provável não encontrar.

Procura binária (diminuir para reinar)

int binSearch(int a[], int n, int x) {
    int left = 0, right = n - 1;
    while (left <= right) {
        int middle = (left + right) / 2;      // divisão inteira
        if (a[middle] == x) return middle;
        if (a[middle] > x) right = middle - 1;
        else left = middle + 1;
    }
    return -1;
}
Resultados
  • B(n) = 1 iteração (x está no meio).
  • W(n) = 1 + ⌊log₂ n⌋ iterações = altura da árvore de decisão (n = 1000 ⇒ 10). O(log n), com sucesso ou insucesso.
  • Para n = 2ᵏ − 1 e procura sempre com sucesso: A(n) = log₂(n+1) − 1 + log₂(n+1)/n ≈ W(n) − 1.
  • Com probabilidade de sucesso p: A(n) ≈ log₂(n+1) − p.
  • Cada iteração faz até 2 comparações, por isso nº de comparações ≈ 2 × nº de iterações.

6 · Algoritmos de ordenação elementaresestudado ✓

In-place

Só usa um nº constante de variáveis auxiliares (não precisa de um array extra de tamanho n).

Estável

Elementos com a mesma chave mantêm a ordem relativa inicial.

Array de índices

Para registos grandes, troca-se só os índices num array auxiliar.

Selection sort

void selectionSort(int a[], int n) {
    for (int k = n - 1; k > 0; k--) {          // coloca o maior na posição k
        int indMax = 0;
        for (int i = 1; i <= k; i++)
            if (a[i] >= a[indMax]) indMax = i;   // última ocorrência do maior
        if (indMax != k) swap(&a[indMax], &a[k]);
    }
}

Bubble sort (com paragem)

void bubbleSort(int a[], int n) {
    int k = n, stop = 0;
    while (stop == 0) {
        stop = 1; k--;
        for (int i = 0; i < k; i++)
            if (a[i] > a[i + 1]) { swap(&a[i], &a[i + 1]); stop = 0; }
    }
}

Insertion sort

void insertElement(int sorted[], int n, int elem) {   // sorted[0..n-1] ordenado
    int i;
    for (i = n - 1; (i >= 0) && (elem < sorted[i]); i--)
        sorted[i + 1] = sorted[i];                     // desloca para a direita
    sorted[i + 1] = elem;
}
void insertionSort(int a[], int n) {
    for (int i = 1; i < n; i++)
        if (a[i] < a[i - 1]) insertElement(a, i, a[i]);
}
AlgoritmoComparações B / W / ATrocas ou deslocamentos B / W / ANotas
Selectionn(n−1)/2 sempre: Θ(n²)0 / n − 1 / n − Hₙ ≈ n − ln n: O(n)"Pouco inteligente": compara tudo mesmo ordenado. In-place, não estável
Bubble (com stop)n − 1 / n(n−1)/2 / ≈ n²/3 − n/60 / n(n−1)/2 / ≈ metade. Trocas = nº de inversõesMelhor caso: array ordenado (1 passagem). In-place, estável
Insertionn − 1 / (n−1)(n+2)/2 / ≈ n²/4 + 7n/40 / n(n−1)/2 / ≈ n²/4Adapta-se: quase ordenado (cada elemento a ≤ k posições) ⇒ O(n·k). Estável com < estrito
Trocas médias do selection sort = n − HₙNo subarray de tamanho k, o maior já está na posição certa com probabilidade 1/k, e então não se troca. Somando: Σ_{k=2}^{n} (1 − 1/k) = (n − 1) − (Hₙ − 1) = n − Hₙ. Para n = 6 dá 3,55, confirmado a correr o algoritmo sobre as 720 permutações.
Exemplo [7, 2, 6, 4, 3]
  • Selection: 4+3+2+1 = 10 comparações, 1+1+0+1 = 3 trocas.
  • Bubble: 4+3+2+1 = 10 comparações, 4+2+1+0 = 7 trocas (= nº de inversões).
  • Insertion: 1+2+3+4 deslocamentos mais as comparações de controlo: 14 comparações e 11 atribuições no total (contando a colocação de cada elemento).
Respostas aos exercícios de Ordenação II e III
  • In-place = memória extra constante → V. Selection sort com troca é estável → F (a troca salta por cima de iguais).
  • Selection em [6,5,4,3,2,1]: 15 comparações e 3 trocas → c. "Pouco inteligente" → b. Trocas no caso médio → O(n).
  • Bubble em [6,5,4,3,2,1]: 15 comparações e 15 trocas → c.
  • Bubble em [6,5,2,3,4,1]: crescente faz 12 trocas (12 inversões); decrescente faz 3 trocas (15 − 12) → c.
  • Trocas do bubble = nº de inversões → b. Se stop não muda na 1.ª passagem → termina após n − 1 comparações e 0 trocas → b. Versão sem stop → a.
  • V/F: piores casos de comparações e trocas podem ocorrer em configurações diferentes → V (ex.: [2,3,…,n,1] também precisa de n − 1 passagens mas só faz n − 1 trocas); insertElement faz no máximo n comparações e n deslocamentos → V.
  • Insertion em [6,5,4,4,2,1]: crescente faz 20 comparações (não 15); decrescente já está ordenado, 0 atribuições (não 25) → d. Confirmado por simulação.
  • Melhor caso do insertion → O(n). Elementos a ≤ k posições → O(n·k). Vantagem sobre selection em arrays quase ordenados → b. Versão tradicional → b.
  • V/F finais: deslocamentos no pior caso n(n−1)/2 → V; estável com < → V; bubble e insertion lineares no melhor caso → V.

Programação dinâmicaUsa-se quando há subproblemas sobrepostos: em vez de os resolver repetidamente, resolve-se cada um uma vez e guarda-se o resultado numa tabela (normalmente de forma iterativa, do mais pequeno para o maior).

Listas ligadas, pilhas e filas

  • Nó = valor + ponteiro para o seguinte. Um nó cabeçalho guarda o ponteiro para o 1.º nó e o tamanho.
  • Inserir/remover no início O(1); procurar O(n); inserir ordenado O(n).
  • Pilha (stack, LIFO): push/pop no topo. Fila (queue, FIFO): insere no fim, remove no início. Ambas O(1) com lista ou array circular.

Árvores binárias

  • O nível i tem no máximo 2ⁱ nós (raiz no nível 0). Uma árvore completa (todos os níveis cheios) com n nós tem log₂(n+1) níveis e (n+1)/2 folhas.
  • Travessias: pré-ordem (raiz, esq, dir), em-ordem (esq, raiz, dir; numa BST dá os valores ordenados), pós-ordem (esq, dir, raiz), por níveis (usa uma fila).
  • BST: tudo na subárvore esquerda < nó < tudo na direita. Procura, inserção e mínimo custam a altura: O(log n) se equilibrada, O(n) se degenerada.
  • AVL: para cada nó, as alturas das subárvores diferem no máximo 1 (rotações para reequilibrar).
  • Árvore guardada num array por níveis: filhos de i em 2i+1 e 2i+2 (binária); 3i+1, 3i+2, 3i+3 (ternária).
  • Heap (fila com prioridade): árvore completa em array onde cada pai ≥ filhos (max-heap). Inserir e remover o máximo O(log n). Heapsort: construir uma max-heap (para ordem crescente) e retirar sucessivamente o máximo: O(n log n).

Tabelas de dispersão (hashing)

Função de hash mapeia a chave para um índice. Colisões resolvem-se por encadeamento (lista em cada posição) ou endereçamento aberto (sondagem linear/quadrática, duplo hashing). Com fator de carga controlado, procura/inserção O(1) em média; O(n) no pior caso.

Grafos

  • Representação: matriz de adjacências (O(V²) de espaço) ou listas de adjacências (O(V + E)).
  • Grafo não orientado completo: n(n−1)/2 arestas. Orientado completo: V listas com V(V−1) nós no total.
  • BFS (largura, por níveis) usa uma fila; DFS (profundidade) usa uma pilha ou recursão. Ambas O(V + E) com listas.
  • Fortemente conexo (orientado): há caminho de qualquer vértice para qualquer outro ⇒ nenhum vértice isolado.
  • Circuito hamiltoniano: passa uma vez por cada vértice e volta ao início. Euleriano: passa uma vez por cada aresta.

P, NP e NP-completo

  • P: problemas de decisão resolúveis em tempo polinomial por um algoritmo determinista.
  • NP: problemas cuja solução pode ser verificada em tempo polinomial (P ⊆ NP).
  • NP-completo: os mais difíceis de NP (ex.: caixeiro viajante na versão de decisão, satisfazibilidade). Instâncias grandes não se resolvem em tempo útil, por isso usam-se soluções aproximadas ou heurísticas.

1. Ordenação por seleção (menor para a 1.ª posição)

void SelectionSort(int* a, unsigned int n) {
    if (n < 2) return;
    for (unsigned int k = 0; k < n - 1; k++) {
        unsigned int indMin = k;
        for (unsigned int i = k + 1; i < n; i++)
            if (a[i] < a[indMin]) indMin = i;      // < estrito: 1.ª ocorrência
        if (indMin != k) {                         // só troca se for preciso
            int tmp = a[k]; a[k] = a[indMin]; a[indMin] = tmp;
        }
    }
}
b) Comparações

C(n) = Σ_{k=0}^{n−2} Σ_{i=k+1}^{n−1} 1 = Σ_{k=0}^{n−2} (n − 1 − k) = (n−1) + (n−2) + … + 1 = n(n−1)/2, para qualquer configuração. Ordem Θ(n²).

c) Trocas
  • Melhor caso: 0 trocas, com o array já ordenado.
  • Pior caso: n − 1 trocas, uma por passo. Por exemplo [n, 1, 2, …, n−1] ou [2, 3, …, n, 1]. Atenção: o array por ordem inversa não é pior caso (só faz ⌊n/2⌋ trocas).
  • Caso médio: no passo com k elementos por ordenar, o menor já está na 1.ª posição com probabilidade 1/k. A(n) = Σ_{k=2}^{n} (1 − 1/k) = (n − 1) − (Hₙ − 1) = n − Hₙ ≈ n − ln n − 0,577. Ordem O(n).

Testado: [6,5,4,3,2,1] faz 15 comparações e 3 trocas; [6,1,2,3,4,5] faz 5 trocas; a média sobre as 720 permutações de 6 elementos dá 3,55 = 6 − H₆.

2. Fusão de duas listas ligadas ordenadas

typedef struct node { unsigned int value; struct node* next; } node, *node_pointer;
typedef struct header { unsigned int size; node_pointer first; } header, *header_pointer;

static node_pointer NewNode(unsigned int v) {
    node_pointer p = malloc(sizeof(node));
    if (p == NULL) exit(1);
    p->value = v; p->next = NULL;
    return p;
}

header_pointer Merge(header_pointer seq_1, header_pointer seq_2) {
    header_pointer res = malloc(sizeof(header));
    if (res == NULL) exit(1);
    res->size = 0; res->first = NULL;
    node_pointer p1 = (seq_1 != NULL) ? seq_1->first : NULL;
    node_pointer p2 = (seq_2 != NULL) ? seq_2->first : NULL;
    node_pointer last = NULL;
    while (p1 != NULL || p2 != NULL) {
        unsigned int v;
        if (p2 == NULL)      { v = p1->value; p1 = p1->next; }   // só resta a 1.ª
        else if (p1 == NULL) { v = p2->value; p2 = p2->next; }   // só resta a 2.ª
        else if (p1->value <= p2->value) { v = p1->value; p1 = p1->next; }  // <= mantém estabilidade
        else                 { v = p2->value; p2 = p2->next; }
        node_pointer q = NewNode(v);                 // copia: as originais ficam intactas
        if (last == NULL) res->first = q; else last->next = q;
        last = q;
        res->size++;
    }
    return res;
}
b) Comparações entre elementos
  • Só se compara enquanto as duas listas têm elementos.
  • Melhor caso: min(n₁, n₂). Todos os elementos da lista mais curta são ≤ ao 1.º da outra (ex.: [1,2,3] com [7,8,9,10] faz 3 comparações). Se uma estiver vazia, 0.
  • Pior caso: n₁ + n₂ − 1. As listas intercalam-se e só falta um elemento no fim (ex.: [1,3,5] com [2,4,6] faz 5).
  • Ambos O(n₁ + n₂) no número de nós criados.

3. Árvore binária de procura

typedef struct tnode { int item; struct tnode *left, *right; } tnode, *pointer;

unsigned int CountNonLeafNodes(pointer root) {
    if (root == NULL) return 0;
    if (root->left == NULL && root->right == NULL) return 0;     // folha
    return 1 + CountNonLeafNodes(root->left) + CountNonLeafNodes(root->right);
}

unsigned int CountValuesInRange(pointer root, int a, int b) {
    if (root == NULL) return 0;
    if (root->item < a) return CountValuesInRange(root->right, a, b);  // esquerda toda < a: não visitar
    if (root->item > b) return CountValuesInRange(root->left, a, b);   // direita toda > b: não visitar
    return 1 + CountValuesInRange(root->left, a, b) + CountValuesInRange(root->right, a, b);
}

b) CountNonLeafNodes processa o nó atual e depois as duas subárvores, por isso é uma travessia em pré-ordem (raiz, esquerda, direita). A soma só fica completa depois das chamadas, o que também se pode descrever como pós-ordem; justifica a tua escolha na resposta.

c) A eficiência vem de usar a ordem da BST: se o nó é menor que a, nada à sua esquerda pode estar no intervalo; se é maior que b, nada à direita. Testado com a árvore 50, 30, 70, 20, 40, 60, 80, 35, 45: 4 nós não-folha; 3 valores em [33, 46].

Recurso 2023/24: S(n) = n·S(⌊n/5⌋), S(n) = n para n ≤ 4

double s_rec(unsigned int n) {
    if (n <= 4) return n;
    return n * s_rec(n / 5);        // divisão inteira já faz o floor
}

double s_iter(unsigned int n) {     // programação dinâmica
    if (n <= 4) return n;
    double* s = malloc((n + 1) * sizeof(double));
    if (s == NULL) exit(1);
    for (unsigned int i = 0; i <= 4; i++) s[i] = i;
    for (unsigned int i = 5; i <= n; i++) s[i] = i * s[i / 5];
    double r = s[n];
    free(s);
    return r;
}
Divisões efetuadas
  • Recursiva: D(n) = 0 para n ≤ 4 e D(n) = 1 + D(⌊n/5⌋). Daí D(n) = ⌊log₅ n⌋ para n ≥ 1, ordem O(log n). Exemplos: D(26) = 2, D(130) = 3.
  • Iterativa com DP: uma divisão por cada i de 5 a n, ou seja n − 4, ordem O(n), mais O(n) de memória.
  • Aqui a DP é pior que a recursão, porque a recursão não repete subproblemas (cada chamada faz só uma chamada). Comenta isto na resposta: é o tipo de observação que o professor valoriza.

Testado para n = 0, 13, 26, …, 130: as duas versões dão o mesmo resultado (ex.: S(26) = 130, S(130) = 16900).
